## Сховище даних (localStorage)

Один спільний масив на кожен тип сутності, без окремих ключів на юзера —
принцип: масив зберігає ВСЕ, фільтрація «моє» робиться через `.filter()`
на стороні клієнта (`author === appState.currentUser` /
`owner === appState.currentUser`).

### `autospilnota_questions` — масив питань
```js
{ id, title, text, author, category, timestamp, views, likes,
  likedBy: [], solved: bool,
  answers: [ { author, text, timestamp } ] }
```

### `autospilnota_cars` — масив авто (Гараж)
```js
{ id, owner, make, model, engineCode, year, mileage, createdAt,
  entries: [ { id, title, text, tags: [], timestamp, likes: [] } ] }
```
Свідомі рішення по цій моделі (не міняти без нового обговорення):
- **Без фото** — відкладено до бекенду (base64 в localStorage забив би сховище)
- **Без `isPublic`** — немає реальної авторизації, перемикач створював би
  хибне відчуття приватності
- **Теги вільні, не фіксований список** — юзер вводить текстом через кому,
  автоматично приводяться до `lowercase` + `trim()` при збереженні
  (щоб «Двигун» і «двигун» не розпадались на різні теги)
- **Один спільний масив, не окремий ключ на юзера** — інакше публічна
  стрічка (усі авто всіх користувачів) вимагала б перебору всіх ключів
  `localStorage` замість простого `.filter()`

### `autospilnota_user` — рядок, ім'я залогіненого юзера (або `''`)

## Відомі обмеження / недороблене (свідомо)

- **Немає бекенду** — все в `localStorage` конкретного браузера/пристрою.
  Два різні браузери не бачать даних одне одного. Це стосується Питань,
  Гаража, чату — усього.
- **Bubble-чат на мобільному — НЕ реалізовано, і поламане при спробі.**
  В `style.css` лишились «осиротілі» стилі `.chat-fab`/`.chat-fab-badge`/
  `.chat-sheet-overlay`/`.chat-sheet-close` (нічого на них не посилається
  в HTML/JS зараз). Спроба підключити зламала весь `main.js` (ймовірно
  синтаксична помилка при ручному вставлянні), Dima відкотив зміни.
  **Рішення: не займатись, поки не попросить окремо.** Мобільний `.chat-panel`
  зараз в старому стані (`position:static; max-height:400px`) — просто займає
  місце в потоці сторінки, не bottom-sheet.
- **Чат не персистентний** — `sendMessage()` тільки додає в DOM, не в `localStorage`.
- **Видалення/редагування авто в Гаражі** — відсутнє. Можна тільки додати
  авто і дописувати записи в бортжурнал.
- **Фільтр по тегах бортжурналу** — теги показуються як бейджі на записах,
  але клік по них нічого не фільтрує.
- **«Майстри» і «Форум»** — пункти в хедері ведуть на `#` (мертві посилання).
  Обговорено як майбутні розділи, ще не почато.
- **«Збережене»** в sidebar — теж мертве посилання, функціонал не існує.
- **Реєстрація** — приймає будь-яке ім'я/email, паролі нікуди не зберігаються
  (демо-заглушка замість реальної авторизації).
- Дрібний мертвий код в `main.js`: `const hamburgerBtn` оголошується на
  верхньому рівні файлу (рядок ~478) і одразу ще раз всередині
  `DOMContentLoaded` (рядок ~492) — не помилка (різні scope), просто
  зайвий рядок, можна прибрати принагоді, не пріоритет.

## Рішення, які приймались явно (щоб не переобговорювати)

- **Мапи для «Майстри»** (коли дійде черга): OpenFreeMap для тайлів
  (безкоштовно, без лімітів, комерційне використання дозволене — на
  відміну від MapTiler/Stadia, де free-тариф тільки некомерційний),
  публічний Nominatim для геокодування адрес (вистачить для невеликого
  курованого списку СТО, вносити вручну).
- **Мультимовність (UA/EN)** — відкладено свідомо. Спочатку весь текст
  українською, переклад — окремим проходом, коли інтерфейс стабілізується
  (робити i18n-шар зараз означало б постійно синхронізувати словник
  з текстом, що ще активно змінюється).
- **Дані про авто з зовнішніх джерел** (auto-data.net) — відхилено:
  їхні умови використання прямо забороняють автоматизований скрапінг,
  є тільки платний офіційний API. Не варте того для довідкової інформації,
  яку легко знайти будь-де.
- **«Форум» як окрема вкладка** — під питанням. Категорії, які зазвичай
  туди пропонують (Двигун, Електрика, Підвіска) дублюють наявні категорії
  питань. Якщо робити — тільки як «Обговорення» (пости без обов'язкової
  «правильної відповіді») всередині наявної системи Питань, не окрема
  структура даних.
